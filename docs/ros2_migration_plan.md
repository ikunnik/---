# ROS 2 后续迁移计划

状态：按当前用户优先级推进阶段2，连续绕障既有失败暂缓修复并保留记录。标准ROS相机输入适配已实现，设备实际话题和延迟尚待验收，详见 [相机输入迁移](ros2_camera.md)。阶段1的历史回归情况见 [阶段1记录](ros2_phase1.md)。

## 目标与当前边界

目标是让感知、语音、运动执行、决策与任务调度具有清晰的 ROS 接口，能独立观测、测试和维护，同时保持现有导盲行为。

已完成：

- `ament_python` 包化、`colcon build/test`、`ros2 launch` 统一入口。
- `mission / avoidance / traffic / lane` 四种模式、YAML 启动参数、只检查配置模式。
- 语音与标定资源安装，参数只读，参数节点与运动节点的上下文隔离。
- ROS 包测试19项通过，安装后的四种模式及自定义参数文件通过配置检查。

当前仍是混合架构：`runtime/assembly.py` 创建线程和进程，数据主要通过 `Latest / Queue / Mailbox` 传递；`decisions/` 为可复用的决策核心；相机、语音及姿态控制仍依赖厂家接口。当前 `dry_run` 仅模拟运动，不能作为全离线环境；`use_sim_time` 尚不支持。

迁移期间保持现有绕障整段距离策略、回原路线条件、盲道控制和交通任务含义。路径算法优化另立任务，以便区分通信迁移与算法变化带来的问题。

## 迁移顺序

| 阶段 | 主要交付 | 完成条件 |
|---|---|---|
| 1. 回归基线与接口 | 统一消息定义、参数来源和时钟约定，补齐可复现基线 | 完整检查通过；故障用例和接口版本入库 |
| 2. 相机接入 ROS | 深度、camera0 RGB、camera2 RGB 统一数据入口 | ROS 与原入口对同一帧产生一致数据，断帧可识别 |
| 3. 感知与语音节点 | 障碍剖面、盲道、停止线、红绿灯、语音独立封装 | ROS 输出与原实现一致，语音结果可关联且错误可区分 |
| 4. 运动执行节点 | 单一运动控制出口、动作接口、取消与停止确认 | 决策失联和进程故障可停止；旧动作不复活 |
| 5. 决策与任务节点 | 用 ROS 输入/动作回执驱动现有决策核心 | 四种模式闭环一致，模式切换没有双重控制 |
| 6. 生命周期与交付 | 就绪管理、诊断、完整离线回放、部署说明 | 可从干净环境构建并完成全套回归和受控实机验收 |

每个阶段先在模拟后端或只观测模式验证，达到验收条件后才替换实际控制链。不得让两套控制器同时向运动话题发布指令。

## 阶段1：先建立可比较的基线

1. 处理当前完整检查中的既有失败。已知掉头近障碍测试使用的固定输入与当前净空阈值不一致；应明确固定测试配置或按阈值构造边界数据，保留正确的停止断言，不能简单删除测试。
2. 重新运行完整检查，登记其他失败，区分实现问题与配置漂移；包测试通过不能替代算法测试。
3. 固定一份验收参数快照，记录软件版本、标定文件、语音包和参数哈希。现有 `config.py` 与 YAML 采用单一默认值来源生成，用户部署覆盖文件独立保存，防止长期漂移。
4. 为 `messages.py` 中的数据定义 ROS 消息与转换函数，统一单位、无效值、时间戳、坐标系和任务标识。
5. 明确命令的 `session_id + generation + goal_id`。节点重启产生新会话，旧回执及旧排队动作不能影响新会话。
6. 明确时钟：传感器保留源时间戳，本机另外记录接收时刻；存活与执行超时使用单调时钟。没有源时间戳时显式标记，不能把重复旧帧包装成新帧。

首批验收场景：左右绕障、长障碍、连续障碍、返回原线、无路可走、语音等待、运动中断帧、里程计过期、停止线丢失、红灯等待、盲道恢复、模式切换及退出。

## 阶段2：先接相机，再换通信外壳

先在设备上只读盘点真实话题、消息类型、QoS、编码、单位、时间戳和帧率。厂家的 `rt/camera/...` 名称不等于已能被标准 ROS 客户端直接使用。

- 如果已有可用的标准 ROS 图像话题，直接订阅；确认没有可复用入口后再写 DDS 到 ROS 的桥接。
- 建议对外使用 `sensor_msgs/Image` 和 `sensor_msgs/CompressedImage`；仅在标定数据可信且用途明确时发布对应 `CameraInfo`。
- 每路相机由一个采集入口管理，多个检测节点共享数据，减少 camera2 重复订阅和重复解码。
- 暂时通过适配器将 ROS 图像送回原 worker，先证明输入一致，再拆检测节点。
- 图像QoS和队列长度根据设备实测确定；优先最新帧，不能为了可靠传输而积压过期图像。

验收：同一帧的分辨率、编码、距离单位、源时间戳一致；无帧、坏帧、重复帧可区分；记录端到端延迟和资源占用，确保留有满足现有过期阈值的余量。

## 阶段3：感知与语音独立封装

复用现有计算函数，节点负责订阅、参数、发布和健康状态，不重写识别算法。

| 建议节点 | 复用模块 | 建议输出 |
|---|---|---|
| `obstacle_profile` | `workers/depth_camera.py` 的 `compute_profile` | 中/左/右距离、各区有效性、最近距离、近处比例 |
| `lane_detector` | `workers/lane.py` | 盲道中心、方向、置信度、可见性及原有单线信息 |
| `stop_line_detector` | `workers/stop_line.py` | 停止线可见性、位置、倾角 |
| `traffic_light_detector` | `workers/traffic_light.py` | 颜色、稳定状态、有效性 |
| `voice_player` | `workers/voice.py` | 语音目标接收、执行结果及失败原因 |

图像与感知结果保留源帧关联；“没检测到目标”必须与“检测器没有有效输出”区分。动态启停红绿灯识别、释放停止线处理等行为保留。

语音建议提供 `Speak` 动作接口，传递语义事件而不是让决策层拼接WAV路径。保留播报去重，并区分成功、失败、取消、超时。当前回执仅代表本地发送结束加尾音等待；除非厂家提供播放确认接口，否则不能声称已得到扬声器播放完成确认。紧急语音抢占需验证设备支持后实现。

验收：固定输入集上新旧感知结果一致；旧帧不增加稳定计数；缺文件、发布失败及迟到语音回执不会解除其他任务的等待。

## 阶段4：将运动执行变成唯一的控制出口

这一阶段需要先通过故障注入，再接入真机。

- 将 `MotionExecutor` 与 `motion/` 适配层封装为 `motion_executor` 节点；仅它能向 `/planner/vel_cmd` 发布运动命令、调用厂家姿态与停止接口。
- 提供有类型的 `ExecuteMotion` 动作接口，覆盖距离、转向和现有速度序列；保留执行进度、完成状态、超时和取消语义，不用任意字符串或JSON传控制参数。
- 旧决策线程先通过ROS动作客户端适配器提交请求，保持决策算法与入口不变。
- 模式切换时撤销旧任务权限、取消旧动作并确认停止，随后才接受新模式动作。
- 执行节点独立检测决策心跳、命令有效期和里程计健康；看门狗覆盖距离、转向与速度动作，不能只覆盖当前循环速度动作。
- 区分“收到停止请求”“零速已发出”“动作已终止”和“里程计确认静止”，根据设备实际能力定义停止完成，不能把取消响应当作已停稳。
- 确认机器人底层是否具有指令超时保护。执行节点被强制杀死或主机断网时，应用层无法保证再发出零速；若底层缺少保护，必须先补齐可靠的底层/独立保护机制再切换实际控制。

验收：正常、超时、失败、取消、网络断开、客户端重启和旧回执迟到均覆盖；始终只有一个控制出口。停止指令延迟与实际制动距离分别测量，不能以“消息已发送”代替制动验收。

## 阶段5：迁移决策与任务调度

将 `DecisionEngine`、`ControllerSupervisor` 和 `decisions/` 封装成协调节点。初期将绕障、盲道、交通及掉头逻辑保留在同一协调节点内，继续使用现有控制权仲裁。

- 订阅感知消息、里程计、执行器及语音结果，将快照转换为现有 `DecisionInput`。
- 用ROS定时器驱动决策计算；动作、服务和语音请求异步等待，不能在订阅回调中阻塞整个决策循环。
- 发布当前模式、状态机阶段、停止原因、原路线锚点、横向误差、活动目标和重规划原因。
- 将内部 `Mailbox` 的失效代数和中断规则映射到跨进程任务标识，保留取消后等待匹配停止回执的逻辑。
- 模式切换通过明确的请求/结果接口完成；运动中的切换仍先确认停止。

验收：同一输入与参数下，动作类型、方向、目标距离、完成条件及停止原因与迁移基线一致。允许通信产生已量化的时延，但不允许增加未经检查的运动。返回原路线仍需要位置与航向证据。

## 阶段6：生命周期、诊断与交付

1. 统一启动顺序：驱动/桥接 → 感知和语音 → 运动执行器就绪 → 协调节点激活。
2. 就绪门控要求新鲜输入与执行器可用；进程存活或话题存在不代表可以运动。
3. 为关键节点增加生命周期/健康接口、退出联动、诊断消息和有界日志。控制节点异常后不自动恢复运动，重启后重新完成就绪检查。
4. ROS参数默认仍为只读。确需在线修改时采用白名单、范围校验和停止状态下原子切换，并记录生效版本。
5. 设计完全离线的运行模式：相机、里程计、语音和运动全部可替换。记录真实图像、里程计、感知、决策及动作回执用于回放；播放录制数据时禁止连接真实运动出口。
6. 注入时钟依赖并验证时间跳变、暂停和恢复后，再单独启用 `use_sim_time`；不直接把当前所有 `time.time()` 换成ROS时间。
7. 完成干净环境安装、设备路径配置、资源清单和运维手册；更新实际维护信息与许可证元数据。

## 建议的接口与包边界

以下名称均为拟议接口，当前代码尚未提供：

| 接口 | 用途 |
|---|---|
| `/guide/perception/obstacles` | 障碍剖面消息 |
| `/guide/perception/lane` | 盲道状态 |
| `/guide/perception/stop_line` | 停止线状态 |
| `/guide/perception/traffic_light` | 红绿灯状态 |
| `/guide/motion/execute` | 运动动作接口 |
| `/guide/motion/stop` | 停止请求与状态确认入口，不替代底层保护 |
| `/guide/voice/speak` | 语音动作接口 |
| `/guide/control/set_mode` | 请求模式切换并返回结果 |
| `/guide/state`、`/diagnostics` | 控制状态与健康信息 |

建议逐步形成 `rover_x1_interfaces`（消息与动作）、`rover_x1_core`（纯算法）、`rover_x1_drivers`（厂家适配）、`rover_x1_nodes`（节点外壳）、`rover_x1_bringup`（启动与部署配置）。

不要求一开始就拆齐所有包。新增消息包先作为同一ROS工作空间 `src/` 下的同级包，不能直接嵌在当前已有 `package.xml` 的包根目录下并假定colcon会自动发现。先解决跨包依赖和导入路径，再逐步去掉当前顶层通用模块名。

## 验收与回退规则

- 每阶段保存原运行入口和测试快照，通过显式启动配置选择新旧实现；切换前先停止现有控制进程。
- 新感知节点可并行观测，但影子决策只记录拟执行动作，不连接执行器。
- 任一输入断流、输出堆积、旧目标复活、失去控制权或制动验收不通过时，退回上一个已验收阶段。
- 顺序为纯逻辑测试 → 隔离ROS域集成测试 → 录制数据对比 → 受控实机测试。导盲使用前需分别验证机械运动表现与跟随者交互体验。
- 不把包测试成功、仿真成功或接口连通等同于复杂环境下的导盲性能已通过验证。

下一步具体任务：确认设备标准ROS图像话题及时间戳，必要时实现厂家DDS桥接，然后迁移感知输出节点。连续绕障既有失败继续记录，按照当前优先级暂不修复。
