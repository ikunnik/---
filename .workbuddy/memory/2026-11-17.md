# 2026-11-17

## 停止线误检（黄色障碍→停止线）诊断与修复

**根因（代码证据）**
- `workers/stop_line.py` 原 `detect_stop_line` 只有两道门：HSV 色域 + `min_area_ratio`。**零几何约束**。
- `range_mask` 的 ranges 格式是 `[h_lo, h_hi, s_min, v_min]`，只设下限（stop_line_profile: H 18-48, S≥0.35, V≥0.45），任何高饱和黄都过。
- 原代码算了 `angle`（PCA）但**只作为输出，不参与过滤**。
- 后果链条：`stop_line_trigger_row=0.844` 触发 `decisions/traffic/line.py:24` 停车并 set(traffic_active)。立体障碍的投影底边比同距离地面线更靠下 → 会**提前**触发。

**修复方案（已落地）**
- `workers/stop_line.py`：新增 `DEFAULT_SHAPE` + `_shape_metrics` + `_shape_ok`，在颜色门之后加几何门。四条判据：elongation_min=6.0、length_ratio_min=0.45、thickness_ratio_max=1.0（默认不限制，近处真线很厚，收紧会漏检）、angle_max_deg=45。
- `assets/stop_line_profile.json`：加 `shape` 段，全部可从 profile 覆盖。
- `tools/stop_line_probe.py`（新增）：单组列指标 / 两组算分离度并给建议阈值。用法 `--pos 真线目录 --neg 黄障碍目录`。
- 拒绝时返回 `visible=False, row=0.0`，但保留 `area_ratio/bbox/angle` → 日志可区分"没有黄色"与"有黄色但不像线"。

**核心设计决策：必须用 PCA 主轴/次轴，不能用 bbox 宽高比**
离线数学验证（纯 Python 复算 2x2 协方差解析解，本机无 numpy）：
| 倾斜 | PCA 伸长比 | bbox 宽高比 |
|---|---|---|
| 0° | 63.9 | 63.90 |
| 10° | 65.9 | 5.21 |
| 15° | 68.4 | 3.53 |
| 20° | 72.3 | **2.63 → 误杀** |
| 30° | 85.1 | 1.69 |
同一根线，bbox 宽高比在 20° 航向偏差就崩到 2.63，会把真线当障碍；PCA 伸长比只增不减。
负样本验证：黄锥桶(100x180)=1.81、黄水马(400x150)=2.68、黄箱(200x200)=1.00，全部 <6.0 被拒。
现有测试兼容：selftest 合成线 640x11 → 63.9；align 测试 420 宽 10° 倾斜 → 约 42.6，均通过。

**诚实边界**：几何门解决不了"地面黄漆带"和"横置的黄栏杆/黄横杆"——它们在几何上就是细长条。这两类只能靠深度贴地校验或"仅在红绿灯序列中消费停止线"。

**未完成**：本机无 numpy/cv2，`selftest.py` 与探针均未实跑；必须在 roverx1-dev 容器里验证后上车。

## 实拍图验证（黄色 A 字"请勿泊车"立牌）

环境突破：`/usr/bin/python3` **有 numpy**（只缺 cv2/grpc/PIL），配合 ImageMagick `magick ... RGB:/tmp/x.rgb` 解出原始像素，可以跑真实 `detect_stop_line`。**这是本机唯一能跑真实检测代码的通道**，务必记住。

**修复前行为（实测 5 个取景）**：黄牌进入 ROI 时黄像素占比 1.6%~4.2%（远超 min_area_ratio 0.2%），全部 `visible=True`，且 **row=0.950 > stop_line_trigger_row=0.844 → 当场触发停车并进入红绿灯序列**。不是"偶尔误判"，是必然误判。

**修复后**：同样 5 个取景全部 `visible=False`。

**实拍图暴露的第二个缺陷（比误检更危险）**：黄牌与真停止线在图像里垂直相邻时，逐行连通会并成一个区域，整体 PCA 被拽歪 —— 实测伸长比从 58.09 掉到 **4.23**，真停止线被判掉 → **机器狗冲过路口**。单纯"逐区域拆分"救不了（相邻即连通）。

**最终方案：双通路并列判定（OR）**
- 通路 A（`_shape_ok`）：细长 + 横贯 + 不过厚 + 不竖立，三量均为 PCA 旋转不变量 → 覆盖**倾斜的真线**（实测倾斜 15°/25° 通过，全宽行=0）。
- 通路 B（`_full_rows`）：某几行的连续黄色 ≥ 80% ROI 宽，且行数 ≥ 3 → 覆盖**障碍物与线粘连**（PCA 失效时只有按行看才分得开）。任何障碍物都做不到让整行连续黄色占 80%+。
- 实测黄牌：全宽行=0、伸长比 1.4~3.0、被黑字红标切成 5~13 个连通块 → 双通路都拒。
- 12 场景回归全通过（黄牌近/远/很宽、两黄牌、细竖杆、只有线、粘连、远处线、倾斜 15°/25°、selftest 合成线）。
- 兼容性：selftest [22]/[22b] 三条断言手工复现全部通过，row 精确 0.8125。

**图里另一个必须知道的事实**：背景地板上就有真实黄色标线（左侧斜线 + 远处横线）。左侧斜线 elongation=18（很像线），靠 **angle_max_deg=45 才拦住**（实测角度 -65.3°）。所以 angle 判据不是可选项，它拦的是"地面导引线"这类最容易混的东西。

**仍待现场确认**：手机竖拍视角 ≠ camera2（640x480 俯视地面）。参数默认值已用合成场景 + 手机照片双重验证，但最终必须在真机采帧跑 `tools/stop_line_probe.py --pos 真线 --neg 黄牌` 定阈值。
